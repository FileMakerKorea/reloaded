# Grilling + Loopy + 90점 검증

RELOADED의 핵심 KPI는 **생각한 것이 실제 화면에 나타나기까지 걸리는 시간**이다. 실패를 조기에 찾아 충분한 품질에 도달하되, 100점을 위한 불필요한 완벽주의로 화면 반영을 늦추지 않는다.

- **Grilling:** 구현·설계를 공격적이고 반대되는 관점에서 검증해 실패 조건과 약점을 찾는다. 사람을 공격하는 것이 아니라 가정과 동작을 반증한다.
- **Loopy:** 구현 → 실행 → 검사 → 실패 발견 → 수정 → 재실행을 자동 반복한다. 승인된 작업 범위 안에서는 사람이 매번 “다시 고쳐”라고 지시할 필요가 없다.
- **90점 검증:** 실행 전에 정의한 관측 가능한 기준으로 100점 만점 평가한다. 90점 미만이면 Loopy로 돌아가고, 90점 이상이며 필수 조건을 충족하면 통과한다.

## 실행 절차

1. **범위와 기준 고정:** 저장소 지침·실행 명령·기존 테스트를 확인한다. 사용자 시나리오, 변경 범위, 기준 버전, 실행 환경, 합격 임계값, 점수표와 반복 예산을 기록한다. 기본 예산은 최초 검증 후 수정·재검증 최대 3회이며, 별도 사용자 예산이 있으면 그것을 따른다. 최초로 요구 화면을 확인한 시간과 검증 완료 시간을 구분해 기록한다.
2. **검증 계획 작성:** 각 평가 항목을 기대 결과, 실행 방법, 배점, 증거 위치에 연결한다. 요구사항별 비중을 먼저 정하고, 사소한 테스트를 늘려 점수를 부풀리지 않는다. 변경 영향에 맞는 경계·회귀 시나리오를 선택한다.
3. **구현·실행:** 최소한의 필요한 변경을 만들고 실제 명령으로 빌드·검사를 실행한다. UI 변경은 브라우저에서 대표 사용자 흐름과 화면을 확인한다. 설계만 있는 작업은 검증 가능한 불변식·예시·반례로 평가하며 실행 검증 완료라고 표현하지 않는다.
4. **Grilling:** 아래 질문 중 변경과 관련된 것을 재현 가능한 사례로 만든다. 발견 사항마다 심각도, 재현 입력·순서, 기대값·관측값, 근거를 남긴다. 추정 문제와 실제 재현 실패를 구분한다.
5. **채점:** 최신 변경 상태에 해당하는 증거로 항목별 점수를 합산하고 필수 조건을 확인한다. “AI가 보기에 93점” 같은 주관적 자가점수만으로 통과시키지 않는다.
6. **Loopy:** 미달 원인 중 위험과 영향이 큰 것부터 수정한다. 실패한 검사와 영향받는 회귀 검사를 재실행하고, 최종 상태의 필수 검사를 완료한다. 변경으로 무효가 된 이전 결과는 재사용하지 않는다.
7. **종료·보고:** 아래 조건으로 통과·미달·검증 보류를 판정한다. 통과 후에는 새 실패 근거나 추가 요청 없이 점수를 올리기 위한 반복을 계속하지 않는다.

## Grilling 질문

- 실패 조건·경계: 빈 값, null, 최솟값·최댓값, 중복 이름, 잘못된 타입, 대량 데이터에서 기대 동작을 유지하는가?
- 회귀: 기존 저장·조회·편집 흐름, 취소·되돌리기, 이전 버전 복원 후 호환성은 유지되는가?
- 동시성: 두 사용자의 동일 객체 변경, 재시도·중복 요청, 부분 실패가 유실·중복·불완전한 트랜잭션을 만드는가?
- 외부 의존성: API 지연·단절·오류 응답, 스키마나 버전 변경 때 실패를 감지하고 복구하는가? 모의 응답으로 검증한 부분과 실제 연동 결과를 구분했는가?
- Metadata: DB와 metadata JSON의 누락·불일치·손상, stable ID와 표시 이름 변경, 삭제된 필드의 계산 의존성, broken binding을 감지하는가? 복원 시 다른 객체를 잘못 참조하지 않는가?
- UI·성능·보안: 화면 조작이 실제 데이터에 반영되는가? 콘솔 오류, 과도한 DOM·렌더링 비용, 권한 우회·입력 검증 누락이 있는가?

모든 작업에 모든 사례를 강제하지 않는다. 제외한 위험은 범위와 이유를 남긴다. 새 자동 테스트는 실제 실패나 중요한 불변식을 검증할 때 추가한다.

## 기본 점수표 예시

| 항목 | 배점 | 관측 가능한 기준 예시 |
|---|---:|---|
| 기능 정확성 | 30 | 요구 시나리오 20, 경계·실패 복구 10. 테스트 통과수/전체수와 실제 결과 기록 |
| UI 일치 | 20 | 기준 화면·상태·반응형 체크리스트 15, 제한된 주관적 시각 품질 5 |
| 기존 기능 보존 | 20 | 영향 범위 회귀 검사 10, console error 0 확인 5, broken binding 0 확인 5 |
| 코드 품질 | 10 | 빌드 성공 5, 저장소 정적 검사·타입·규칙 준수 5 |
| 성능 | 10 | 동일 조건의 응답·렌더링 시간, DOM·메모리·bundle 측정 중 사전 지정한 임계값 충족 |
| 보안 | 10 | 변경 관련 권한·입력·데이터 노출 검사와 기존 보안 기준 충족 |
| 합계 | 100 | 90점 이상 및 필수 조건 충족 |

세부 체크마다 배점을 미리 나눠 `획득 점수 = 통과한 체크의 배점 합계`로 계산한다. 비율 채점이 적합한 경우에만 사전 정의한 `배점 × 통과수 / 전체수`를 사용한다. 계산은 소수점 그대로 비교하고 89.9를 반올림해 통과시키지 않는다.

주관적 UI 품질은 전체 5점 이내로 제한하고, 기준 이미지·평가 이유를 붙여 객관 점수와 분리한다. 성능은 기기·브라우저·데이터 크기·측정 횟수와 기준값을 기록한다. CHECK-01 관련 변경이라면 직접 편집·metadata 계층의 overhead를 기준 구현과 비교한다. 모든 작업에 대규모 벤치마크를 요구하지 않는다.

문서·설계 등 특정 항목이 적용되지 않으면 **실행 전에** 사유와 대체 기준·배점을 정하고 합계 100점을 유지한다. 미실행 검사는 N/A나 통과로 바꾸지 않고 미확인·0점 처리한다. 환경 문제로 필수 증거를 확보하지 못하면 검증 보류다. 결과를 본 뒤 실패 항목을 제거하거나 기준·분모를 낮춰 통과시키지 않는다. 요구사항 변경으로 기준을 바꿨다면 이유와 새 버전을 기록하고 영향 항목을 다시 검증한다.

## 종료·재시도 조건

- **통과:** 90/100 이상, 사전 지정 필수 검사 전부 통과, 현재 변경 상태의 필수 증거 확보, 중대한 미해결 결함 없음. 적용되는 빌드·핵심 사용자 흐름, 데이터 무결성 및 보안 필수 검사는 다른 점수로 상쇄할 수 없다.
- **자동 재시도:** 90점 미만 또는 필수 검사 실패이며, 승인된 범위에서 수정 가능하고 예산이 남아 있으면 Loopy를 계속한다. 실패 원인과 다음 수정 가설을 기록한다.
- **미달 종료:** 반복 예산 소진 또는 동일 원인에 대한 수정·재검증 2회 연속 진전 없음. 통과로 포장하지 말고 남은 실패, 시도한 해결책, 필요한 다음 결정을 보고한다.
- **검증 보류:** 환경·권한·외부 의존성 부재로 필수 검사를 실행할 수 없거나 작업 범위 결정이 필요하면 의존 작업을 멈추고 필요한 정보만 요청한다. 독립적으로 가능한 검증은 진행한다.
- **권한 경계:** 반복 개선은 기존 승인 범위 안에서 수행한다. 점수 통과 자체가 배포·운영 DB 변경·외부 메시지·push 권한을 만들지 않는다. 이미 승인된 작업은 재승인 요청 없이 수행한다.

## 결과 보고 형식

다음 양식을 실제 값과 증거 링크 또는 파일 경로로 채운다. 민감한 로그·토큰은 노출하지 않는다.

```text
판정: 통과 / 미달 / 검증 보류 — 총점 x/100, 객관 x/95 + 주관 UI x/5
범위·버전: 요구사항, 기준 SHA, 검증한 SHA 또는 미커밋 변경 식별
환경·기준: 실행 환경, 점수표 버전, 필수 조건, 반복 예산
KPI: 시작 시각 → 최초 화면 확인까지 시간 / 검증 완료까지 시간

항목 | 획득/배점 | 명령·시나리오 | 실제 결과 | 증거
기능 정확성 | ...
UI 일치 | 객관 ... / 주관 ...
기존 기능 보존 | ...
코드 품질 | ...
성능 | ...
보안 | ...

Grilling: 발견 사항, 심각도, 재현 방법, 수정·미해결 상태
Loopy: 회차별 실패 → 수정 → 재검증 결과, 점수 변화
필수 조건: 항목별 통과/실패/미확인 및 근거
남은 위험·미실행 검사: 영향과 이유, 필요한 후속 조치
종료 이유: 90점 및 필수 조건 충족 / 예산 소진 / 진전 없음 / 차단 요인
```

배점을 사전 조정했다면 보고 양식의 항목·객관/주관 분모도 실제 점수표에 맞춘다. 실행하지 않은 검사의 숫자를 예시에서 가져와 보고하지 않는다.
