# RELOADED 프로토타입 검증 결과

검증일: 2026-09-26 KST, macOS arm64. 기준 main `16b8129235bf35ad411cec731ddc93cbc4027a2d`, 작업 브랜치 `codex/reloaded-prototype`. 운영 배포 없음. 기존 저장소와 업무 데이터는 변경하지 않고 별도 worktree·격리 PostgreSQL·합성 레코드로 검증했습니다.

## 판정

사전에 기록한 [기준](validation-plan.ko.md)에 대해 **100/100, 필수 조건 통과**입니다. 이는 아래 범위의 로컬 프로토타입 판정입니다. 제품 완성, 실제 Spring 호환, 상용 법률 검토 완료를 의미하지 않습니다. 후속 요청에 따라 실제 1,000개 객체의 이동·크기 조절을 각각 50회 측정해 사전에 미확인으로 남긴 5점을 보완했습니다. 제한된 로컬 시나리오의 통과이며 제품 전체 완성도를 뜻하지 않습니다.

## 실행 증거

`npm run typecheck`, `npm test`(8/8), `npm run verify:db`, `npm run verify:mcp`, `npm run verify:security`, `npm run build`, `npm run licenses`가 통과했습니다. `npm run verify:codex`는 기존 인증으로 실제 합성 요청을 완료했습니다. 외부 서비스 검사는 재실행 시 계정·네트워크 상태에 영향을 받습니다. npm audit 취약점 0건은 해당 설치 시점 결과이며 보안 감사를 대신하지 않습니다.

- [DB 결과](evidence/db.json): PostgreSQL 16.14, 12개 동시 identity 발급의 유일성, 삭제 이후 F013, 트랜잭션 rollback, insert/read, 빈 이름 거부, 정본+COMMENT rename, 오래된 revision 거부.
- [MCP 결과](evidence/mcp.json): 실제 stdio SDK 호출, 프로젝트 읽기·너비 patch의 디스크 지속, 오래된 revision 거부.
- [Codex 결과](evidence/codex.json): 인증 상태 확인, 실제 응답 `RELOADED 연결 확인 완료`. UI에서도 합성 연결 요청의 응답을 확인했습니다. 요청 패널은 제안 전용이며 코드 자동 적용은 구현하지 않았습니다.
- [보안 결과](evidence/security.json): 외부 Origin/Host 403, 인증 누락 401, 잘못된 스키마 400, 비밀 파일의 일반·대문자·인코딩·Vite 경로 모두 403. 응답에 비밀번호가 없음을 검사했습니다. 침투 테스트 전체를 뜻하지 않습니다.
- [실행 빌드](evidence/build.json): JS 228,209 bytes(gzip 71,303), CSS 4,484(gzip 1,560). 실제 module graph에 editor/model JSON 의존성이 없고 source map 및 편집 UI 표식이 없습니다. React 고지를 포함했습니다.
- [라이선스 목록](evidence/licenses.json): 설치된 152개 의존성의 SPDX 메타데이터에 UNKNOWN 없음. Electron/Chromium의 전체 하위 구성요소 출시 심사는 남아 있습니다.

## 실제 브라우저 확인

내장 브라우저로 다음 동작을 수행했습니다. DOM 측정과 상태 확인을 함께 사용했으며 스크린샷만으로 통과시키지 않았습니다.

1. 고객명 너비/높이 360×64 입력 → 실행 모드에서 같은 크기와 핸들 제거 확인. 오른쪽 드래그 408, 아래 88, 모서리 440×104로 실제 모델 변경 확인.
2. 복제 입력창의 새 UUID와 입력창 수 2 → undo 1 → redo 2 확인. 복제를 취소하고 저장한 크기를 새로고침 후 재확인.
3. 일반 클릭은 선택, ⌘+클릭은 실행. 팝업의 확인 버튼을 선택·편집했고 일반 클릭으로 팝업이 닫히지 않았습니다. 화면 이동 시 이전 선택이 해제됩니다.
4. 합성 목록의 37번째 행 내부 텍스트를 클릭해 해당 레코드 UUID 선택 확인, ⌘+클릭으로 상세 팝업 확인. 반복 템플릿 자체 편집은 미구현입니다.
5. 객체 Y=760, 캔버스 스크롤 395인 상태에서 +24/+16 드래그 → X=56/Y=776 확인. 임의 중첩 CSS transform 전체 조합은 검증하지 않았습니다.
6. 격리 DB 연결, 빈 이름 오류, 합성 고객 저장 및 목록 반영 확인. 4173 실행 빌드에서도 합성 레코드 저장 성공.
7. 실제 GitHub 저장소를 격리 imports 폴더로 clone하고 모델 없는 기존 프로젝트 열기 확인. 이 경우 환경 안내만 표시하며 자동 변환을 주장하지 않습니다.
8. 대량 모델 편집 도중 빌드가 새로고침을 유발하던 문제 수정 후, 저장 전 너비 88이 빌드를 거쳐 유지됨을 확인했습니다.
9. 최종 예제는 두 입력창 320×48, revision 2로 저장했습니다. 실행 앱 실측 320×47.995(브라우저 소수점 반올림), 편집 핸들 0개. 최종 편집·실행 탭의 오류 로그는 각각 빈 배열입니다.

## CHECK-01 성능

[방법과 재현 명령](check-01-method.ko.md), [동일 DOM 통제 실험 27개 표본](evidence/check-01.json), [실제 앱 9개 표본](evidence/check-01-actual.json)을 함께 보세요. 아래 실제 앱은 규모별 1회로 분포·p95를 나타내지 않습니다.

| 객체 수 | 실행 앱 렌더 ms | 편집기 load ms | 편집 geometry ms | 실행 JS bytes |
|---:|---:|---:|---:|---:|
| 100 | 33.1 | 26.2 | 26.9 | 264,930 |
| 1,000 | 43.4 | 65.9 | 27.8 | 608,900 |
| 10,000 | 502.3 | 669.4 | 139.2 | 4,075,650 |

실행은 module 평가 후 mount, 편집 load는 API 읽기부터 시작하므로 두 열의 차이를 편집 비용으로 단순 차감할 수 없습니다. 다운로드·파싱 전체 시간, 강제 GC 후 메모리, 스타일·layout trace는 미측정입니다. 10,000개에서 편집 geometry 후 heap 약 120.8MB를 관측했지만 GC·히스토리 영향을 분리하지 않았습니다. 통제 실험의 baseline/runtime은 같은 일반 React DOM이고 editor만 속성·이벤트·핸들을 더한 비교입니다. 실제 앱에서는 객체당 DOM 3개, 선택 시 4개가 추가됐습니다.

10,000개 정적 JSX는 약 4MB이며 1,000/10,000 빌드에 청크 크기 경고가 발생했습니다. 가상화·분할 로드·반복 템플릿 컴파일은 구현하지 않았습니다. 대규모 편집 성능이 충분하다고 판단하지 않습니다.

[KPI 기록](evidence/kpi.json)의 숫자 입력 2회→DOM 읽기 16ms는 자동화 관측치입니다. 사람의 생각·입력 시간과 실제 paint 완료 시간이 아니므로 “누구나 16ms에 수정” 같은 주장을 할 수 없습니다. 첫 사용 가능 화면까지의 전체 작업 시간은 정밀 계측하지 않았습니다.

## 수정·재검증 기록

검증에서 발견한 문제를 수정한 뒤 관련 검사를 다시 수행했습니다. 저장소의 제한된 반복 검증 원칙에 따라 광범위한 반복 점수 최적화는 하지 않았습니다.

- DB 동시 발급 테스트에서 volatile 함수의 복합 결과를 펼치는 테스트 SQL이 중복 호출을 유발했습니다. `SELECT * FROM 함수(...)`로 수정하고 12개 유일 발급·F013을 확인했습니다.
- 설치된 Codex App Server의 sandbox enum이 문서 예시와 달랐습니다. 설치 스키마로 맞추고 실제 응답을 확인했습니다. 상속 도구·플러그인·MCP를 제한한 제안 세션을 사용합니다.
- 생성 코드의 표시 이름 escaping과 비밀 파일 접근 차단을 보완했습니다. 정적 번들 검사 및 HTTP 거부 검사를 통과했습니다. Host 검사 도구가 헤더를 보존하지 않는 문제는 실제 HTTP 요청 방식으로 교정했습니다.
- 모델 없는 프로젝트의 예제 표시와 프로젝트 전환 DB 연결 잔류를 수정했습니다. 새 프로젝트는 연결을 다시 선택합니다.
- 대량 실험 중 임시 HTML 변경으로 인한 화면 새로고침을 발견했습니다. work/dist/.local 감시를 제외하고 미저장 편집 유지 확인을 마쳤습니다.
- 스크롤 자동화는 이벤트 반영 전 좌표를 읽어 실패했습니다. 실제 스크롤 반영 후 DOM 좌표를 읽어 검증했으며 이 도구 타이밍 실패를 앱 성공으로 바꾸어 기록하지 않았습니다.

## 남은 범위

실제 Spring 프로젝트와 인증 연동, 범용 소스/DOM 역매핑, 반복 템플릿 편집, 반응형 재배치, 타입 migration, DB와 Git의 자동 reconciliation, 다중사용자 권한, 운영 인증, 서명된 Electron 설치본은 미구현 또는 미검증입니다. Electron 창 실행은 확인했지만 배포 패키지를 만들지 않았습니다. 최종 Electron 보안 옵션은 정적 확인이며 별도 OS UI 회귀검사는 하지 않았습니다.

파일 저장은 revision·원자적 rename·잠금으로 보호하지만 비정상 종료 시 잠금 디렉터리 수동 복구가 필요할 수 있습니다. DB 정본과 COMMENT는 트랜잭션이며 Git JSON 스냅샷과는 분산 원자성이 없습니다. 격리 개발 DB의 관리 권한을 운영 권한 설계로 그대로 사용하면 안 됩니다.

[법적 보고서](legal-risk-review.ko.md)는 청구항·관할·권리 상태와 상표의 추가 전문가 확인이 필요한 사전 검토입니다. RELOADED 이름 사용 가능성이나 특허 비침해를 확정하지 않았습니다.

## 후속 검증: 실제 포인터 조작 p95

요청 범위: 기존 미검증 성능 한 항목의 증거 보완. 재개 시 origin/main을 다시 fetch하고 현재 브랜치의 포함 관계를 확인했습니다. 기능 최적화나 제품 범위 확장은 하지 않았습니다. `?measure=1` 편집기에만 포인터 이벤트 계측을 추가했습니다.

[110회 전체 원자료](evidence/check-01-pointer.json)에는 워밍업 10회와 본 측정 100회가 모두 들어 있습니다. 이동·모서리 resize 각각 워밍업 5회 후 본 측정 50회, 실패 표본 제외/재측정 없음. 실제 브라우저 포인터 down→중간 이동→최종 이동→up으로 조작했습니다. 두 동작을 번갈아 수행했고 각 동작은 +16/+16과 -16/-16 이동을 교대로 사용했습니다. 1,000개 실제 객체 전체가 렌더된 상태이며 히스토리도 실제로 쌓였습니다.

| 동작 | 표본 | 마지막 이동→프레임 p50 | p95 | 최대 | 전체 gesture p95 | 자동화 호출·읽기 p95 |
|---|---:|---:|---:|---:|---:|---:|
| 이동 | 50 | 33.5ms | 66.7ms | 89.4ms | 219.5ms | 404ms |
| 모서리 resize | 50 | 33.5ms | 50.2ms | 66.7ms | 212.7ms | 403ms |
| 합산 | 100 | 33.5ms | 66.6ms | 89.4ms | 214.4ms | 403ms |

측정 경계는 마지막 pointermove 처리 진입(스냅/모델 검증/렌더 전)부터 pointerup과 히스토리 반영을 거친 두 번째 requestAnimationFrame까지입니다. OS 입력 대기·첫 pointerdown의 선택/복제 비용은 주 지표에 포함하지 않습니다. gesture 열도 pointerdown 준비 이후부터이므로 완전한 입력 지연 측정은 아닙니다. 두 RAF는 화면 갱신 기회에 대한 관측치이며 GPU 표시 완료 보장은 아닙니다. 사람의 생각·판단 시간을 계측하지 않았고, 자동화 전체 시간과 주 지표를 혼동하지 않습니다. p95는 정렬 후 ceil(n×0.95)번째 값입니다.

환경: Apple M5 Pro, 메모리 48GiB, macOS 27.0(26A428), Node 26.4.0, Vite 7.3.6 개발 모드, Codex 내장 Chromium, viewport 1422×800. 별도 CPU/network throttling은 설정하지 않았고 배경 부하는 통제하지 않았습니다. 정확한 브라우저 엔진 버전은 DOM 도구에서 노출되지 않아 미기록입니다. navigator 조회 1회 실패는 측정 완료 후 환경 수집 도구의 제한이며 조작 오류 수에 섞지 않았습니다.

조작 오류 0/100, 모델↔DOM 좌표 불일치 0/100, 렌더된 크기 오차 0.02px 초과 0/110(워밍업 포함), 브라우저 error 로그 0. 단일 기기·고정 경로의 결과로 모든 실제 프로젝트·드래그 속도에 일반화하지 않습니다. 긴 드래그의 매 프레임 지연, 입력 큐 및 compositing trace는 미측정입니다.

관련 회귀: 타입 검사·기존 8개 테스트·기본 production build 분리 검사를 통과했습니다. 측정용 변경은 실행 빌드에 들어가지 않습니다. 측정 후 미저장 fixture를 다시 열어 버리고 예제 프로젝트로 복구했습니다. 미저장 상태에서 프로젝트 전환이 비활성화되는 정상 보호를 확인했으며 데이터 유실을 위한 우회는 하지 않았습니다.

실제 기존 개발 서버를 종료한 뒤 README의 `npm start`를 실행하여 격리 DB 준비와 5173 서버 시작을 확인했습니다. 기존 4173 preview 서버도 정상이며 [재시작 증거](evidence/restart.json)에 기본 편집기/실행 앱 모두 320×48, 실행 핸들 0, error 로그 0을 기록했습니다. 서버는 로컬 프로세스로 남겨 두었지만 재부팅·앱 종료 후의 지속 실행을 보장하지 않습니다. 다음 날에는 README의 재실행 절차로 시작할 수 있습니다.
